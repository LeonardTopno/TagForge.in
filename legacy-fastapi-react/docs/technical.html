Technical overview

Architecture, data model, API surface, configuration, and how credits and the TVS LP 46 NEO browser-print workflow are implemented in this repository.

Application overview Status and plans README

Stack

Backend

FastAPI 0.115, SQLAlchemy 2 async, Pydantic Settings, Uvicorn. Passlib/bcrypt for passwords, python-jose JWT for sessions.

Frontend

React 19, Vite 6, TypeScript. Single-page UI in frontend/src/App.tsx. Code 128 bars in barcode.ts. Icons from lucide-react. Auth token in localStorage.

Data and runtimes

SQLite via aiosqlite for local runs. PostgreSQL 16 + asyncpg under Docker Compose. Tables created on startup.

Tenancy and auth

  • A Shop is the tenant. Users belong to one shop via shop_id.
  • Roles: owner, operator, admin. Admin routes call require_admin().
  • Register creates shop + owner, hashes the password, and writes a credit ledger grant.
  • Login and /me return a JWT plus nested user and shop payloads.
  • Tag list, create, print, settings, dashboard, and billing queries always filter by current_user.shop_id.

Net weight is gross − stone − other_deduction on the API (Create Tag UI sends gross and stone; net preview uses gross − stone). Negative net weight is rejected with HTTP 422.

Insufficient credits return HTTP 402. Duplicate email or duplicate item name returns 409. Admin without role admin returns 403. Oversized logos return 413.

Credits algorithm

  • charge_tag_credits no-ops when credits ≤ 0 or unlimited_until is still in the future.
  • Expired credits_expire_at zeros the shop balance before charging.
  • Create tag charges 1 credit. Print and reprint do not charge.
  • Paid credit plans add credits and extend expiry; unlimited plans extend unlimited_until.
  • Tag price and signup grant come from settings: TAG_PRICE_INR, FREE_REGISTRATION_CREDITS.

Frontend behaviour

  • Shop UI views: create, history, billing, settings (shop / tag / items).
  • Responsive layout: fixed sidebar on desktop; slide-out menu with backdrop on screens under 900px; stacked grids and horizontal table scroll on smaller widths.
  • Create Tag: item dropdown from /settings/items, Gold/Silver radios, gross and stone weights, live net weight (gross − stone), Save / Save & Print / Test Print.
  • Preview renders one PrintableTag: left panel weights, centre fold mark, right panel category + item + Code 128 + tag number. Labelled “single side, fold at centre”.
  • Shop logo is uploaded as multipart/form-data. The API returns logo_url (/uploads/logos/{shop_id}.ext). The sidebar shows it; the hang tag does not.
  • Path /admin-portal swaps in the admin shell (same SPA, no router library).
  • Preview sizes one hang-tag face from shop millimetre fields. Code 128 barcode in frontend/src/barcode.ts.
  • Print uses CSS @media print — one page (@page { size: 80mm 18mm }). Print rules hide navigation chrome and keep tag colours with print-color-adjust.
  • frontend/src/api.ts wraps fetch; VITE_API_BASE_URL overrides the API host.

Mapping to frontend layout

PrintableTag in frontend/src/App.tsx renders a horizontal barbell strip with a single printable face:

print-tag grid:  [ tag-printable-face ] | tag-neck (2.5mm) | tag-tail (18mm)

tag-printable-face grid:  tag-panel-left (weights) | tag-fold-mark | tag-panel-right (item + barcode)

On an 80 mm-wide tag, the printable face occupies the left portion; neck and tail are structural (not printed). Weights and barcode share one printed side; the user folds on .tag-fold-mark. Item label uses category + item name (e.g. “Gold Ring”).

Print CSS uses @page { size: 80mm 18mm }. Per-shop tag_width_mm and tag_height_mm drive the on-screen preview; @page is not yet dynamic — calibration should account for this until print CSS follows shop settings.

Counter PC / driver settings

  • Media type: gap or black mark (match the roll)
  • Label size: custom ~80 mm × 18 mm
  • Orientation: landscape for the strip
  • Scale: 100% — do not fit to page
  • Margins: none or minimum
  • Printer selection in browser dialog: TVS LP 46 NEO

TVS LP 46 NEO browser-print workflow

The app is built for the TVS LP 46 NEO label printer. Printing uses the browser print dialog, not direct USB from the server. The operator selects TVS LP 46 NEO in that dialog.

Create Tag renders one PrintableTag in a print-bundle. Print CSS keeps only that bundle visible. One page prints the full face: left weights, centre fold mark, right item + Code 128 of tag_number + the human-readable number. Neck and tail are not printed.

Millimetre layout comes from Settings → Tag Settings (tag_width_mm, tag_height_mm, font_size_pt, offsets). Tag Settings also shows printer model and “single-side print, fold at centre” guidance. Shop logos live under backend/uploads/logos/ (gitignored).

Local run

Without Docker: venv + uvicorn app.main:app --reload in backend/, and npm run dev in frontend/. With Docker: docker compose up --build starts Postgres 16, API on 8000, Vite on 5173. SQLite schema migrations for extra shop columns are applied in create_database() for local files only.

Known gaps

  • Razorpay Orders/payments are stubbed with local order/payment ids.
  • No Windows USB print agent yet.
  • Operator role exists on the model but registration only creates owners.
  • Dynamic @page size from shop Tag Settings (currently fixed at 80 × 18 mm).
