Technical overview

Architecture, data model, API surface, configuration, and how credits and the TVS LP 46 NEO browser-print workflow are implemented in this repository.

Stack

Backend

FastAPI 0.115, SQLAlchemy 2 async, Pydantic Settings, Uvicorn. Passlib/bcrypt for passwords, python-jose JWT for sessions.

Frontend

React 19, Vite 6, TypeScript. Single-page UI in frontend/src/App.tsx. Code 128 bars in barcode.ts. Icons from lucide-react. Auth token in localStorage.

Data and runtimes

SQLite via aiosqlite for local runs. PostgreSQL 16 + asyncpg under Docker Compose. Tables created on startup.

Tenancy and auth

  • A Shop is the tenant. Users belong to one shop via shop_id.
  • Roles: owner, operator, admin. Admin routes call require_admin().
  • Register creates shop + owner, hashes the password, and writes a credit ledger grant.
  • Login and /me return a JWT plus nested user and shop payloads.
  • Tag list, create, print, settings, dashboard, and billing queries always filter by current_user.shop_id.

Net weight is gross − stone − other_deduction, quantized to 3 decimals. Negative net weight is rejected with HTTP 422.

Insufficient credits return HTTP 402. Duplicate email or duplicate item name returns 409. Admin without role admin returns 403. Oversized logos return 413.

Credits algorithm

  • charge_tag_credits no-ops when credits ≤ 0 or unlimited_until is still in the future.
  • Expired credits_expire_at zeros the shop balance before charging.
  • Create tag charges 1 credit. Print and reprint do not charge.
  • Paid credit plans add credits and extend expiry; unlimited plans extend unlimited_until.
  • Tag price and signup grant come from settings: TAG_PRICE_INR, FREE_REGISTRATION_CREDITS.

Frontend behaviour

  • Shop UI views: create, history, billing, settings (shop / tag / items).
  • Responsive layout: fixed sidebar on desktop; slide-out menu with backdrop on screens under 900px; stacked grids and horizontal table scroll on smaller widths.
  • Create Tag: item dropdown from /settings/items, Gold/Silver radios, live net weight, Save / Save & Print / Test Print.
  • Shop logo is uploaded as multipart/form-data. The API returns logo_url (/uploads/logos/{shop_id}.ext). The sidebar shows it; the hang tag does not.
  • Path /admin-portal swaps in the admin shell (same SPA, no router library).
  • Preview sizes two hang-tag faces from shop millimetre fields. Back barcode is Code 128 in frontend/src/barcode.ts.
  • Print uses CSS @media print and prints front then back as two pages. Print rules hide navigation chrome and keep tag colours with print-color-adjust.
  • frontend/src/api.ts wraps fetch; VITE_API_BASE_URL overrides the API host.

TVS LP 46 NEO browser-print workflow

The target printer is the TVS LP 46 NEO. Create Tag renders two PrintableTag faces in a print-bundle. Print CSS keeps only that bundle visible. Page 1 is front weights; page 2 is back item + Code 128 of tag_number + the human-readable number. The hanging tab is empty on both faces. Offsets come from shop settings. The operator selects the TVS LP 46 NEO in the browser print dialog. Shop logos are stored under backend/uploads/logos/ and served at /uploads; that folder is gitignored.

Local run

Without Docker: venv + uvicorn app.main:app --reload in backend/, and npm run dev in frontend/. With Docker: docker compose up --build starts Postgres 16, API on 8000, Vite on 5173. SQLite schema migrations for extra shop columns are applied in create_database() for local files only.

Known gaps

  • Razorpay Orders/payments are stubbed with local order/payment ids.
  • No Windows USB print agent yet.
  • Operator role exists on the model but registration only creates owners.
  • Physical TVS LP 46 NEO calibration of front/back hang-tag print is still pending.
