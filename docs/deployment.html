TagForge deployment

Print tags. Run your shop.

Deploy the PHP / MySQL / Bootstrap app to shared hosting (cPanel). All production hosts share one document root; Apache + .htaccess + includes/hosts.php choose shop, app, admin, or API by hostname.

HostURLEntry
Shophttps://tagforge.inindex.php
Mobile apphttps://app.tagforge.inapp.php
Adminhttps://admin.tagforge.inadmin.php
APIhttps://api.tagforge.inapi.php

1. Requirements

  • PHP 7.4+ with pdo_mysql, sessions, and file uploads
  • MySQL 5.7+ or MariaDB 10.3+
  • Apache with mod_rewrite (standard on cPanel)
  • Hosting plan that allows at least 3 subdomains (admin, app, api) plus the main domain
  • SSL for apex + subdomains (AutoSSL / Let’s Encrypt)

2. What to upload

Upload the project into the main site document root, usually:

/home/ACCOUNT/public_html/

Include: index.php, app.php, admin.php, api.php, install.php, .htaccess, includes/, assets/, uploads/, docs/ (optional).

Do not rely on legacy-fastapi-react/ in production. It is a source backup. Prefer omitting it from the upload. .htaccess blocks web access if it is present.

Permissions: includes/ and uploads/ (and uploads/logos/) should be writable by PHP — typically 755 or 775.

3. MySQL

  1. In cPanel → MySQL Databases, create a database (e.g. tagforge_app).
  2. Create a database user with a strong password.
  3. Add the user to the database with ALL PRIVILEGES.
  4. Note the full database name and username (cPanel often prefixes them, e.g. tagforge_app).
  5. Host is almost always localhost.

4. DNS

tagforge.in          A / ALIAS   → hosting IP
www.tagforge.in      CNAME      → tagforge.in
app.tagforge.in      CNAME/A    → same host
admin.tagforge.in    CNAME/A    → same host
api.tagforge.in      CNAME/A    → same host

These are subdomains of tagforge.in, not separate registered domains.

5. Subdomains in cPanel

Create admin.tagforge.in, app.tagforge.in, and api.tagforge.in under Domains → Create A New Domain.

Document root must be the same as the main site — usually /home/…/public_html (or the relative path public_html).
  • If Share document root with tagforge.in is available, check it.
  • If that checkbox is greyed out, type the path manually: /home4/ACCOUNT/public_html (use your real home path).
  • If create fails with a subdomain limit, upgrade the plan or free a subdomain slot (this app needs three).

Redirects

Prefer letting project .htaccess route hosts. In cPanel → Redirects:

  • Do not redirect admin / app / api wholesale to https://tagforge.in/$1. That breaks host routing.
  • Safe examples (optional; duplicate what .htaccess already does):
    • admin.tagforge.in/ → admin.php
    • app.tagforge.in/ → app.php
    • api.tagforge.in/ → api.php
    • tagforge.in/admin.php → https://admin.tagforge.in/
    • tagforge.in/app.php → https://app.tagforge.in/
  • HTTPS force that keeps the host is fine, e.g. redirect to https://%{HTTP_HOST} for *.tagforge.in.

SSL

In cPanel → SSL/TLS Status (or AutoSSL), issue certificates covering tagforge.in, www, admin, app, and api. Wait until all show valid before testing login across hosts.

6. Configuration

Copy includes/config.example.php to includes/config.php (or let install.php write it), then set at least:

'db_host' => 'localhost',
'db_name' => 'YOUR_DB_NAME',
'db_user' => 'YOUR_DB_USER',
'db_pass' => 'YOUR_DB_PASSWORD',
'secret_key' => 'long-random-string',

'urls' => [
  'shop'  => 'https://tagforge.in',
  'admin' => 'https://admin.tagforge.in',
  'app'   => 'https://app.tagforge.in',
  'api'   => 'https://api.tagforge.in',
],
'hosts' => [
  'shop'  => ['tagforge.in', 'www.tagforge.in'],
  'admin' => ['admin.tagforge.in'],
  'app'   => ['app.tagforge.in'],
  'api'   => ['api.tagforge.in'],
],
'cookie_domain' => '.tagforge.in',
'mail_from' => 'noreply@tagforge.in',
'razorpay_key_id' => '',
'razorpay_key_secret' => '',

cookie_domain .tagforge.in shares the login session across shop, app, admin, and API. Leave Razorpay keys empty until you enable live billing.

7. Run the installer

  1. Open https://tagforge.in/install.php.
  2. Confirm environment checks (PHP, PDO MySQL, writable folders).
  3. Enter MySQL credentials and optional admin account.
  4. On success, delete install.php from the server.

8. Verify

  • https://api.tagforge.in/api.php?r=health returns {"status":"ok"}
  • https://tagforge.in/ shows shop login / register
  • https://app.tagforge.in/ shows mobile app entry
  • https://admin.tagforge.in/ shows admin portal
  • Register a shop, create a tag, open Actual Preview, test browser print
  • Sign in on shop, confirm session still works when calling the API host
  • Upload a shop logo (writes under uploads/logos/)

Visiting https://api.tagforge.in/ with no route returns Unknown API route — that is expected. Always use ?r=… (e.g. health).

9. After go-live

  • Delete install.php.
  • Keep includes/config.php off public git; it is gitignored.
  • Confirm includes/, scripts/, and uploads/mail_outbox/ are blocked by .htaccess.
  • Set real razorpay_key_id / razorpay_key_secret before charging shops.
  • Create at least one user with role admin for admin.tagforge.in (installer can do this).

10. Updating the app

  1. Back up includes/config.php and the MySQL database.
  2. Upload changed PHP/JS/CSS files over the existing docroot (do not overwrite config.php or wipe uploads/).
  3. If schema changed, apply the matching SQL/migration notes for that release (or re-run only additive migrations).
  4. Hard-refresh the browser or bump cache on assets/ if CSS/JS looks stale.

11. Troubleshooting

SymptomLikely fix
Cannot create third subdomainPlan subdomain limit; upgrade or remove an unused subdomain
Share document root checkbox disabledSet document root path manually to public_html
admin/app always open the shop siteRemove redirects to tagforge.in/$1; confirm docroot is shared
Login lost across hostsSet cookie_domain to .tagforge.in; use HTTPS everywhere
Database error on healthCheck config.php credentials; confirm DB user privileges
Logo upload failsMake uploads/logos writable; raise PHP upload limits if needed
500 after uploadConfirm .htaccess is present; check error log in cPanel
